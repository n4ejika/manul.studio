CAUSE / 01

First, identify what actually restricts the website.

The constraint may be structure, content, technology, speed, analytics or the enquiry path — not only appearance.

That is why the redesign scope is decided only after reviewing the current website and its evidence.

TASK CHECK

Sometimes redesign is the wrong solution.

Diagnosis compares the cost of preserving the current system with building a new website without unnecessary legacy.

REDESIGN 0–35%

added to development

A visual refresh without complex migration adds 0–10%. Preserving structure, content and organic performance adds 10–20%. CMS, URL, form and integration migration adds 20–35%.

A problematic legacy system is estimated separately; a premium of up to 50% is an exception, not the default.
NEW WEBSITE ×1,0

new development

If there is little worth preserving and the old architecture and technology only add constraints, a new website with a clean structure may be cheaper and safer than a redesign.

A new website may still launch on the current domain; required redirects and data migration remain part of the scope.

FAQ

Key questions before a redesign begins.

Can current rankings be guaranteed?+

No. Diagnosis, URL mapping, redirects and post-launch control reduce risk, but search results cannot be guaranteed.

Must the CMS be replaced?+

No. The decision depends on current constraints, support costs and the website’s future tasks.

Can the redesign be phased?+

Yes, when the architecture and technology allow incremental releases without breaking data or user journeys.
